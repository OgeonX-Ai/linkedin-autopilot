## 1. Scope Statement

This ISMS applies to the **OgeonX LinkedIn Autopilot** system in its entirety, including:

### 1.1 Systems in Scope

| System Component | Description |
|---|---|
| MCP Server application | TypeScript/Node.js process exposing MCP tools and HTTP endpoints |
| Hono HTTP layer | Routes: `/auth/*`, `/oauth/*`, `/mcp`, `/routine/*`, `/admin/*`, `/` |
| Session persistence | `.sessions.json` file on the host filesystem |
| User registry | `.users.json` file on the host filesystem |
| Runtime configuration | `.env` file containing all secrets and credentials |
| Cloudflare Tunnel | HTTPS ingress — `trycloudflare.com` or custom domain |
| Build artifacts | Compiled JavaScript in `dist/` |

### 1.2 Data in Scope

- LinkedIn OAuth 2.0 access tokens and refresh tokens
- LinkedIn user profile data (name, email address, LinkedIn `sub` identifier)
- LinkedIn organization page identifiers (`LINKEDIN_ORG_ID`)
- Application credentials: `SESSION_SECRET`, `LINKEDIN_CLIENT_SECRET`, `LINKEDIN_CLIENT_ID`, `API_KEYS`, `ADMIN_SECRET`
- Post content composed by AI agents (transient — not stored on server)

### 1.3 Processes in Scope

- LinkedIn OAuth 2.0 authorization code flow (user authentication)
- JWT issuance and verification for ChatGPT/Google Agentspace agent integration
- API key authentication for n8n, Zapier, and direct HTTP clients
- LinkedIn API calls: posting updates, reading profiles, managing company pages
- External feed fetching: Remotive.io, Indeed RSS, TechCrunch, MIT Tech Review, O'Reilly
- Git repository introspection via `getRecentCommits` tool

### 1.4 Boundaries Out of Scope

- LinkedIn's own infrastructure and data centers
- Cloudflare's network infrastructure
- End-user AI agent platforms (Claude Desktop, ChatGPT, Google Agentspace)
- Content generated by AI models before being passed to MCP tools

## 2. ISMS Objectives

The ISMS is designed to ensure the following security properties for LinkedIn credentials and user data:

### 2.1 Confidentiality
- LinkedIn OAuth tokens are stored server-side only and are never transmitted to MCP clients or AI agents.
- `LINKEDIN_CLIENT_SECRET` and `SESSION_SECRET` are held exclusively in environment variables and are redacted in all log output and error responses.
- API keys and the admin secret are never returned in any HTTP response.

### 2.2 Integrity
- Session cookies are HMAC-SHA256 signed; tampering is detected and rejected via `timingSafeEqual`.
- JWTs are HS256-signed with `SESSION_SECRET`; signature verification uses `timingSafeEqual` to prevent timing attacks.
- OAuth CSRF state tokens (32 hex characters, 16 bytes of entropy from `crypto.randomBytes`) prevent authorization code injection.
- Post content is passed directly to the LinkedIn API without server-side storage, eliminating a class of integrity risks.

### 2.3 Availability
- The server performs startup validation of all required environment variables (`config.ts`); it exits immediately rather than starting in a degraded/insecure state.
- Expired sessions are purged automatically every 15 minutes to prevent memory exhaustion.
- Cloudflare Tunnel provides HTTPS availability without requiring inbound firewall rules on the host.

## 5. Information Security Policy Statement

OgeonX LinkedIn Autopilot is committed to protecting the confidentiality, integrity, and availability of all LinkedIn credentials and personal data processed through the system.

The following principles govern all development and operational decisions:

1. **Least privilege**: The application requests only the LinkedIn API scopes required for its declared functions (`openid`, `profile`, `email`, `w_member_social`, `w_organization_social`, `r_organization_social`, `rw_organization_admin`). No read-access-only profile scopes beyond what OpenID Connect provides are requested.

2. **Secrets never leave the server**: LinkedIn access tokens, refresh tokens, and all application secrets are held in server-side memory and `.sessions.json`. They are never transmitted in HTTP responses, MCP tool results, or log output.

3. **Defense in depth**: Multiple authentication methods (signed cookies, HS256 JWT, API key, ADMIN_SECRET) each provide independent enforcement. Failure of one layer does not bypass others.

4. **Cryptographic integrity**: All session identifiers and JWTs are signed with HMAC-SHA256. Signature verification uses constant-time comparison to resist timing-based attacks.

5. **Startup security gate**: The server refuses to start if required secrets are absent or undersized (`SESSION_SECRET` must be at least 32 characters).

6. **Error sanitization**: Error responses are sanitized to prevent secret leakage. `LINKEDIN_CLIENT_SECRET` is redacted from all outputs.

7. **LinkedIn API Terms of Service compliance**: The application operates within LinkedIn's permitted use cases. No scraping, no undocumented endpoints, no automation that exceeds rate limits.

This policy is reviewed annually by the ISMS Owner or following any significant security incident.
